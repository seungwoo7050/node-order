상태: 확정(사람)
브랜치: 34-catalog-admin (앞 브랜치: 33-member-guest)
문제: 스토어프론트(/shop)와 관리자(/admin/*)가 같은 상단 메뉴(Nav)와 880px 좁은 레이아웃을 같이 써서 손님 화면에 관리 메뉴가 섞이고 관리자 화면은 좁고 메뉴가 흩어져 있다. 더 큰 문제는 DB에 어떤 회원이 있는지 볼 화면(/admin/users)도, 새 상품을 등록할 화면(/admin/products/new)이나 삭제할 기능도, 카테고리를 관리할 화면(/admin/categories)이나 쇼핑몰 카테고리 필터도 없으며, 단일 SKU만 되어 의류·라이프스타일 자사몰의 필수인 옵션(사이즈·컬러)을 다룰 수 없다는 점이다. 또한 개발자가 아닌 판매자가 웹 화면에서 자신의 PG·AI·메일 API 키를 직접 등록해 켜거나 인프라·비용 상태를 보고 제어할 곳이 없다.
결정:
  - 스토어프론트와 관리자 백오피스의 레이아웃 쉘을 완전히 분리한다(/admin/layout.tsx, 1280px 와이드 워크스페이스 + 좌측 사이드바). 손님 상단바(nav.tsx)에서는 관리자 메뉴를 빼고 관리자로 로그인했을 때만 조용한 [스토어 관리] 진입 링크 하나만 둔다 / 대안: 기존 상단바에 메뉴를 더 늘리기. 메뉴가 10개를 넘어 손님 화면이 깨진다 / 바꿀 신호: 어드민을 아예 별도 도메인 앱으로 분리해야 할 때
  - 상품 옵션은 ProductVariant(id, product_id, name, sku, price_delta, stock, sort_order) 모델로 두고, order_items와 return_items의 복합 기본키를 (order_id, product_id, variant_key)로 넓힌다(옵션 없는 상품은 variant_key = 0) / 대안: 2단계 옵션 그룹 매트릭스. 1인 자사몰에서는 "블랙 / M" 같은 단일 계층 품목 옵션으로 모든 조합을 직관적으로 표현할 수 있고 재고 잠금도 단순하다 / 바꿀 신호: 옵션 축이 3개 이상이고 축별 독립 가격 규칙이 필요해질 때
  - 옵션이 있는 상품을 주문할 때는 product_variants 행을 SELECT ... FOR UPDATE로 잠그고 차감하며, 부모 products.stock도 옵션 재고 합계와 맞춘다. 취소·반품 환불 때는 해당 variant_id의 재고를 복구한다
  - 백오피스에서 DB의 모든 핵심 엔티티(상품·옵션, 카테고리, 회원·비회원, 주문·송장·반품)를 조회·생성·수정·삭제(Full CRUD)할 수 있게 완결한다. 이미 주문 이력이 있는 상품이나 회원을 삭제할 때는 결제·대사 장부가 깨지지 않게 판매중지(is_visible = false) 또는 개인정보 비식별화로 처리하고, 주문 이력이 없으면 즉시 삭제한다
  - 29-admin의 바꿀 신호("개발자가 아닌 판매자가 직접 키를 넣어야 할 때")에 따라 DB 암호화 비밀 금고(IntegrationSecret, AES-256-GCM, 키는 JWT_SECRET 파생)를 둔다. 관리자가 /admin/system에서 키를 저장·삭제하면 서버 재시작 없이 결제·AI·메일·주소 API가 즉시 켜지거나 꺼지고, 모든 GET 응답에는 평문 대신 마스킹 요약(maskedPreview)만 나간다
  - /admin/system에 DB 테이블별 전체 행 수, 연결된 인프라(API·DB·Redis·스토리지) 상태와 과금 성격 분류표, 유료 API 일괄 차단(pause_paid_apis), 상점 영업 휴면 모드(maintenance_mode), 클라우드 절전·철거(90-destroy.sh) 안내 패널을 둔다
  - 관리자 대시보드(/admin)는 기존 5개 타일 필드를 유지하면서 6단계 주문 파이프라인 퍼널, 최근 7일 매출 추이, 회원·비회원 주문 비중, 베스트셀러 TOP 5, 품절 임박 옵션을 더한다. 주문 목록(/admin/orders)에는 키워드 검색(?q=...)과 택배 발주용 CSV 다운로드(/admin/orders/export.csv)를 더한다
완료 기준:
  1. /admin/* 경로는 스토어프론트 Nav/Footer 없이 독립된 백오피스 사이드바 레이아웃으로 열리고, /shop에는 관리자 메뉴 대신 쇼핑 메뉴와 카테고리 필터 바가 보인다
  2. 관리자가 /admin/products/new에서 옵션(예: 블랙/M, 블랙/L)과 소재정보·사이즈가이드를 가진 새 상품을 등록하고 수정·숨김·삭제할 수 있다
  3. 같은 상품의 서로 다른 두 옵션을 한 주문에 담아 결제하면 각 옵션의 재고가 정확히 줄고, 취소·반품 승인 시 해당 옵션의 재고가 복구된다
  4. /admin/categories에서 카테고리를 추가·이름 변경·이동·삭제할 수 있고, /admin/users에서 회원·비회원을 검색·조회·수정·삭제(비식별화)할 수 있다
  5. /admin/system에서 API 키(예: LLM_API_KEY, TOSS_CLIENT_KEY 등)를 저장하면 서버 재시작 없이 /features와 관련 기능이 즉시 켜지고, 어떤 조회 응답에도 입력한 평문 비밀값이 나오지 않는다(마스킹만 노출). pausePaidApis를 켜면 LLM 기능이 즉시 꺼지고, maintenanceMode를 켜면 신규 주문이 503으로 막힌다
  6. /admin/orders에서 주문번호·주문자·받는분·연락처로 검색할 수 있고, export.csv로 UTF-8 CSV를 내려받을 수 있다
  7. npm run verify 통과. 기존 29-admin 대시보드·설정·비밀값 분리 테스트를 포함해 모든 테스트가 통과한다
범위 밖: 멀티테넌트(한 DB에 여러 판매자 상점 격리), 클라우드 VM 자체를 웹 앱 내부에서 강제 종료하는 기능(물리적 자기 종료 한계로 런북 명령 패널로 제공)
외부 의존: 없음
