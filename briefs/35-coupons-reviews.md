상태: 확정(사람)
브랜치: 35-coupons-reviews (앞 브랜치: 34-catalog-admin)
문제: 자사몰 운영에 필수인 프로모션 할인 수단(쿠폰 코드)이 없고, 상품을 사서 구매확정한 손님이 후기와 별점을 남길 수 없어 상품 상세 페이지에 구매 근거(리뷰)가 없다.
결정:
  - 쿠폰은 할인 코드형(coupons: code unique, name, discount_type fixed|percent, discount_value, min_order_amount, max_discount_amount, max_uses, used_count, active, starts_at, expires_at)으로 둔다. 회원과 비회원 모두 장바구니에서 코드를 입력해 쓸 수 있다 / 대안: 회원별 쿠폰함 발급 테이블. 비회원 주문과 첫 방문 프로모션(웰컴 코드)에는 코드형이 가장 직관적이다 / 바꿀 신호: 등급별 개인화 쿠폰 자동 발급이 필요해질 때
  - 주문할 때 쿠폰 코드가 있으면 coupons 행을 SELECT ... FOR UPDATE로 잠그고 조건과 한도를 검사한 뒤 used_count를 1 올린다. 주문의 total_amount는 Math.max(0, 상품합계 - 할인금액) + 배송비로 저장해 PG 승인 금액과 일일 대사(compare.ts)가 그대로 맞아떨어지게 한다. 주문이 취소되면 used_count를 1 뺀다
  - 리뷰(reviews)는 반드시 주문 상태가 confirmed(구매확정)인 주문의 소유자(회원 또는 비회원 주문 토큰)만 그 주문에 담긴 상품에 대해 주문당 1회(UNIQUE(order_id, product_id)) 쓸 수 있다. 작성자 이름은 마스킹(예: 김*우)해 저장하고 구매한 옵션 이름(variant_name)을 함께 남긴다 / 대안: 아무 로그인 사용자나 리뷰 작성 허용. 사지 않은 사람의 허위 후기가 섞인다 / 바꿀 신호: 포토 리뷰 이미지 업로드가 필요해질 때
  - 관리자 백오피스에 /admin/coupons(쿠폰 목록·발행·활성/비활성 수정·삭제)와 /admin/reviews(전체 리뷰 조회·상품별 필터·삭제)를 두어 Full CRUD를 완성한다
완료 기준:
  1. 관리자가 /admin/coupons에서 정액·정률 쿠폰을 만들고 수정·삭제할 수 있다
  2. 장바구니에서 유효한 쿠폰 코드를 넣으면 할인 금액이 미리 계산되고, 결제 시 할인된 총액으로 주문과 PG 결제가 이루어지며 대사(Reconciliation)에서 불일치가 나지 않는다. 한도 초과·만료·최소금액 미달 쿠폰은 400/409로 거부되고, 주문 취소 시 쿠폰 사용 횟수가 복구된다
  3. 구매확정(confirmed) 전인 주문이나 남의 주문에서는 리뷰 작성이 400/403/404로 거부되고, 구매확정한 주문에서만 리뷰를 쓸 수 있다(같은 주문·같은 상품에 두 번 쓰면 409)
  4. 작성된 리뷰와 평균 별점·구매 옵션이 상품 상세(/shop/[id])에 보이고, 관리자가 /admin/reviews에서 조회·삭제할 수 있다
  5. npm run verify 통과
범위 밖: 중복 쿠폰 동시 적용, 적립금·포인트, 리뷰 사진 첨부
외부 의존: 없음
